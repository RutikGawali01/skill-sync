# Google Authentication Workflow

## Authentication Flow

```text
User
 │
 │ Opens Website
 ▼
Browser
 │
 ├── Downloads index.html
 │      │
 │      └── Loads Google Identity Services SDK
 │
 ├── Starts downloading Google SDK asynchronously
 │
 └── Starts React Application
             │
             ▼
      Login / Signup Page
             │
             ▼
      Google Sign-In Button Loads
             │
             ▼
      User Clicks Google Button
             │
             ▼
      Google Authentication Popup Opens
             │
             ▼
      User Selects Google Account
             │
             ▼
      Google Verifies User Identity
             │
             ▼
      Google Returns ID Token
             │
             ▼
      Frontend Sends ID Token to Backend
             │
             ▼
      Backend Verifies Token with Google
             │
             ▼
      Create / Retrieve User
             │
             ▼
      Backend Generates Application JWT
             │
             ▼
      Frontend Stores JWT
             │
             ▼
      User Is Authenticated
             │
             ▼
      Redirect to Protected Page
```

# Workflow Explanation

### 1. Load Google Identity Services

When the application loads, the browser downloads the **Google Identity Services (GIS) SDK**. This SDK provides Google's secure authentication functionality and renders the official Google Sign-In button.

---

### 2. User Starts Authentication

The user clicks **Continue with Google**, which opens Google's authentication popup.

Google handles the complete sign-in process, including account selection and credential verification.

---

### 3. Google Returns an Identity Token

After successful authentication, Google generates a **Google ID Token**.

This token contains the authenticated user's identity and is digitally signed by Google.

The frontend **does not trust this token directly**.

Instead, it forwards the token to the backend for verification.

---

### 4. Backend Verifies the Token

The backend validates the received Google ID Token by checking:

- Token signature
- Expiration time
- Intended audience (Client ID)
- Google as the issuer

Only if all validations pass is the user considered authenticated.

---

### 5. User Registration / Login

After successful verification, the backend:

- Creates a new user if it is the user's first login, or
- Retrieves the existing user from the database.

---

### 6. Generate Application JWT

Instead of using Google's token for future requests, the backend creates its own **Application JWT**.

This JWT contains application-specific information such as:

- User ID
- Email
- Role
- Permissions

The backend returns this JWT to the frontend.

---

### 7. Store Authentication Token

The frontend securely stores the application JWT.

This token is included in the `Authorization` header for every protected API request.

---

### 8. User Session Starts

Once the JWT is stored, the user is considered authenticated and is redirected to the protected area of the application.

Subsequent requests use the application JWT instead of requiring the user to sign in again.

---

# Important Concepts

## Google Identity Services (GIS)

Google Identity Services is Google's official authentication library that provides a secure Google Sign-In experience without requiring the application to manage user passwords.

---

## Two Tokens Are Used

### Google ID Token

- Generated by Google.
- Proves the user's identity.
- Used only during the login process.
- Sent to the backend for verification.

---

### Application JWT

- Generated by your backend.
- Represents an authenticated session within your application.
- Stored by the frontend.
- Used for all authenticated API requests.

---

## Why Verify the Google Token?

The frontend cannot determine whether a Google ID Token is genuine.

Only the backend should verify:

- Token authenticity
- Digital signature
- Expiration
- Client ID
- Token issuer

This prevents forged or tampered authentication tokens.

---

## Why Generate a Separate JWT?

Although Google authenticates the user, it does not know anything about your application's users, roles, or permissions.

Your backend generates its own JWT to manage authentication and authorization within your application.

---

## Benefits of This Approach

- Secure authentication using Google.
- No password management required.
- Backend-controlled authorization.
- Stateless authentication using JWT.
- Seamless user experience with Google Sign-In.
- Standard OAuth/OpenID Connect authentication flow.
